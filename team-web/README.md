# AIsMov RackTop 团队工作台

**版本范围：本文对应已发布的 2.8.0。团队网页已上线，Linux 与两种 Mac 的测试版安装包可从下载页获取。新增 GPU 占用摘要需要管理员升级到 2.8.0 并持续采集；旧桌面不会产生该摘要，安装包发布不代表现有管理员电脑已经升级。历史验收不代表本轮结果。**

面向小团队的在线整机 / GPU 预约、资产设备管理和办公设备申请网页，由 AIsMov 在独立仓库 [RackTop-Workspace](https://github.com/AIsMovDataInfra/RackTop-Workspace) 维护。普通成员注册、由超级管理员分配公司并登录后，可用浏览器查看排期、预约资源和维护资产；超级管理员可跨公司管理。网页和桌面通过同一中央 API、SQLite 数据库使用同一份资源目录与排期。导航使用「资产设备管理 / Asset management」「办公设备申请 / Office equipment requests」，地址仍为 `/equipment`、`/requests`；周报入口已从新源码移除。

资产设备管理目录显示设备总数与四种状态数量，可展开公司、类别、位置分布。统计只包含当前身份可见的全部设备，独立于目录搜索和筛选，点击刷新或从详情返回时重新读取；不做定时自动刷新。统计接口无需数据库迁移。现有标签 PDF/PNG 导出及每 15 分钟云端备份继续保留；既往即时备份与 2.4.0 统计部署结果见[2.4.0 历史验证记录](../docs/VERIFICATION_2_4_0.md)。具体使用见[资产设备管理](../docs/EQUIPMENT.md)，备份恢复见[运维说明](deploy/BACKUPS.md)。

默认正式模式是**一个成员名称＋密码**，不需要邮箱、邮件验证码或飞书账号。资源、预约、设备档案和照片均要求有效业务成员身份：超级管理员，或已登录且已分配公司的成员／资源管理员；未登录时只显示静态登录／注册界面，`/api/session` 可创建匿名 CSRF 会话，`/api/health` 仅提供健康状态。预约只登记团队排期，不锁定 GPU，不隔离 Unix 用户，不停止训练进程，也不代表已取得 SSH 权限。终端和文件操作继续使用独立的 RackTop 资源共享功能。

本版成员公司管理、头像、设备录入、密码找回和办公设备申请需使用 `account` 模式。`demo`／`feishu` 尚未提供公司身份，暂不支持新增设备；已登录用户仍可查看和维护已有设备的其他字段及照片。完整录入验收请使用独立的 `account` 测试库；当前线上账号模式不受此限制。

## 成员与管理员的使用流程

1. 打开预约网页，先登录或注册团队账号。直接打开资源、预约或设备二维码链接时，也会先要求登录，具备公司资格后继续原页面。
2. 点击注册，只填写一个成员名称和密码。名称用于登录与显示，支持中英文，去除两端空白后非空即可，不另设长度或字符格式限制、不做 Unicode 规范化，且不可重名；登录忽略两端空格与大小写。密码保留原文、无复杂度或最小长度要求，新密码不能只有空白。旧账号原用户名和显示姓名保留，仍可用原用户名登录。
3. 注册后进入“等待分配公司”。超级管理员分配 `A公司`、`B公司`、`C公司` 或 `西浦` 后，页面会自动继续原链接，也可点击刷新；等待期间仍可退出和在设置中修改自己的密码。之后可预约整机或指定 GPU。姓名显示在预约中，但**姓名不是授权凭据**；服务端使用固定账号 UUID 和登录会话判断操作权限。
4. 成员只能修改、取消或提前结束自己的预约。资源管理员可以管理本公司资源、确认硬件清单并协调本公司成员预约；超级管理员另有“成员管理”，可查看账号目录、添加员工、为员工分配公司、重置密码和删除员工账号。超级管理员不分配公司，普通成员和资源管理员均不能查看成员目录。
5. 登录界面的“记住登录”保持 360 天；关闭时为 8 小时，桌面设备登录仍为 30 天。注册完成的首次登录默认为 8 小时。退出会注销当前网页登录，修改密码会撤销其他网页会话和全部桌面设备登录。

忘记密码时点击登录页“忘记密码？”（也可打开 `?auth=recover`），只提交用户名。无论账号是否存在，都显示相同提示；这只创建待处理申请，不会发邮件或直接改密。超级管理员在“成员管理”看到申请后核实身份，再设置新密码并告知员工；重置撤销该员工全部网页和桌面登录。超级管理员本人的密码可在设置中修改，遗忘时由部署管理员使用下方显式 reset 命令处理。

公司是业务隔离边界，成员只可查看与维护自己公司的资源、预约、设备和照片，超管可跨公司管理。旧记录的公司不明时只对超管可见，核实分配后再向对应公司开放；只有超管能查看成员名册。设置中公司只读，头像可从24种彩色内置SVG选项选择并保存，原7种保持兼容。删除员工会撤销其登录并移除账号凭据，原预约、设备和登记历史保留；同名新账号不会继承旧账号身份。

### 首次创建超级管理员

部署目录、数据库目录和低权限 `racktop-team` 账号就绪后，在开放公共注册前，由部署管理员在服务器 root shell 执行以下命令，显式创建唯一超级管理员。程序默认用户名为 `admin`，密码必须另外输入，服务没有硬编码的默认密码。密码只经受保护的标准输入传入，不能写进命令行、环境模板或仓库：

```bash
systemd-ask-password '输入超级管理员密码' | runuser -u racktop-team -- /opt/racktop-team/node/bin/node /opt/racktop-team/current/scripts/team-admin.mjs create --db /var/lib/racktop-team/team.sqlite --public-url https://136.0.110.161 --username admin
```

超级管理员固定跨公司管理，不分配公司；普通员工由其在成员页分配公司。已有普通账号占用同名用户名时，命令会拒绝抢占或提升权限，需先人工核实。重复执行 create 不改变已存在超级管理员的密码；服务重启也不会恢复初始密码。确需重置超级管理员密码时，将同一命令中的 `create` 改为 `reset`，重新从隐藏输入提供新密码；此操作会撤销该账号的旧网页会话与设备令牌。

### 兼容的一次性资源管理员认领

原认领路径仍可创建 `role:'admin'` 的资源管理员，不授予 `isSuperAdmin:true`，也不自动分配公司。新部署只需超级管理员时可将以下两个可选设置留空。需要此兼容路径时，部署管理员在服务端环境配置中设置高熵随机 `TEAM_BOOTSTRAP_TOKEN`，仅把一次性设置链接交给站点所有者：

```text
https://136.0.110.161/#setup=<一次性认领码>
```

这是站点首页的 URL fragment，不是独立 `/setup` API。页面读取后立即清理地址栏中的认领码，用户自己填写一个成员名称和密码；注册请求通过 HTTPS 将认领码提交给服务端。正确认领码只能创建一次资源管理员，消费状态持久保存在数据库，重启不会恢复可用性。可选的 `TEAM_ADMIN_USERNAME` 会保留指定用户名，只有携带正确认领码才能注册它；留空时由站点所有者自行选择用户名。

第一个普通注册者不会自动成为资源管理员或超级管理员，公开姓名或用户名也不能获得管理员权限。完成认领后可从服务环境移除认领码并重启服务；既有管理员账号不受影响。不要公开分享设置链接，也不要把真实认领码放进 Git、前端构建变量、访问日志或交付文档。

## 与 RackTop 的服务器资源对齐

旧的个人硬件清单同步继续保留：管理员在桌面登录同一预约账号，选择需要加入团队预约的服务器。桌面经现有 SSH 连接采集所选机器的 GPU 清单，并向中央服务上报资源名称、集群、状态、采集时间和 GPU 身份；SSH 主机地址、登录账号、密码、私钥及进程明细不随同步请求上传。桌面持久化的是操作系统钥匙串中的设备令牌，密码不持久保存。

- 每张同步 GPU 必须有真实、完整的 NVIDIA `GPU-…` 硬件 UUID。服务端另分配稳定 GPU ID；预约绑定该 ID，GPU 0 / GPU 1 只是当前显示编号。编号重排不会把原预约转到另一张卡。
- 同一完整 GPU 清单通过不同 SSH 账号或桌面添加时，可关联到同一资源。首个绑定成为清单权威来源，别名连接不能覆盖原资源名称或清单。
- 同一台物理机若两个账号只能看到**互不相交**的 GPU 集合，当前版本无法自动判断它们属于同一机器。应使用能看到完整清单的连接，避免把同机拆成独立资源；不能靠相同名称自动合并。
- 部分可见清单、跨资源 GPU 混合、不受支持的 UUID、占位卡号、MIG 分区或 NPU 编号会拒绝绑定，不会猜测硬件身份。
- 收到缺卡、换卡或卡数变化时，保留旧清单和已有预约，标记“待确认”，阻止新的预约和修改。管理员必须先协调、取消或结束所有尚未结束的有效预约，才可确认新清单；确认还需匹配最新清单版本。
- 最后采集时间超过 90 秒显示 `unknown`，不把“收到旧快照”当作刚刚在线。桌面离线不会删除硬件清单或预约，网页仍可浏览和安排未来排期。
- CPU 服务器可由管理员手工添加，在资源表单选择 CPU，保存为 GPU 数量 0、型号为空，只支持整机预约；GPU 类型须填写型号和 1–64 的整数数量。手工 GPU 资源继续支持按编号预约，但没有已验证的硬件身份；转为同步资源前必须先处理尚未结束的预约。

资源管理员新建或同步的资源属于自己公司；超级管理员新建时可选择公司，无公司身份的超管同步出的未分配资源须在网页补齐公司后开放预约。同步接口不能用客户端参数强行移动资源到其他公司。调整已分配资源公司仅限超管，需最新 `companyVersion` 且不能有未结束的有效预约；已结束预约保留原公司、名称和集群快照。

看板按 **GPU 集群 / CPU 集群** 分类，再按原有集群名称筛选；同名集群在两个类型下分别显示，分类不会把既有集群硬改为“阿里云”。CPU 表单的“阿里云 ECS”仅为名称示例。管理员应按实际节点登记 CPU 资源，用于分类和整机预约；本轮不提供通用 CPU 实时占用监控。

### 组织 GPU 占用摘要（需 2.8.0 管理员桌面）

2.8.1 起，预约看板的硬件资源与启用的服务器资源、成员 SSH 授权对齐。成员只看到获授权服务器已确认的 GPU 资源；管理员和成员看到的同一物理 GPU 占用相同。旧个人同步留下但已脱离服务器目录的硬件资源不再进入看板，历史记录保留；显式手工登记的 CPU 等资源继续遵循组织权限。

如果客户端能 SSH 连接而预约页没有资源，管理员应先在 **RackTop 客户端**登录管理员账号、连接组织服务器并取得完整 GPU 清单；旧未分配硬件首次认领需超级管理员。只在网页登录管理员，或客户端仍以普通成员身份登录，不会执行占用上报。不能仅凭服务器名称手工关联不同机器。无法连接或无法获得完整清单时先处理连接/采集问题，不把未知状态当作空闲。

看板中「所选时段未预约」只表示没有排期冲突。立即开始 GPU 预约还需要所选卡当前明确空闲；忙碌、未知或过期时改选未来时段或刷新确认。忙碌资源仍展示。已有正在进行的预约可以续期，续期检查未来排期冲突，增加 GPU 时核对新增卡占用。


2.8.0 管理员桌面通过本机 SSH 采集当前有权访问的组织服务器，约每 30 秒使用独立 `/api/servers/:id/telemetry` 接口上传 GPU 摘要。关闭本地历史记录后仍会使用内存摘要同步实时占用，不为此额外持久化完整 Snapshot。它与“同步本机资源”的个人硬件清单接口分开，不要求将组织连接伪装成本机个人资源。网页只读取中央 API，不直接连入 SSH。

摘要包含每卡利用率、已用显存及 Linux 系统用户名。看板和预约弹窗分别显示“当前实际占用”与“所选时段预约”：系统用户名不是团队成员姓名或预约人；有进程、利用率或显存占用但没有可用用户名时显示“匿名用户”。`status` 仍表示采集连接状态，`usage.state` 才是 `busy/free/unknown` 占用状态。

只有可靠的完整空闲采样才显示空闲。采样达到 90 秒、旧客户端缺少摘要、缺少足以判断占用或空闲的证据或清单冲突时显示未知；过期摘要不会继续显示旧用户名。空 GPU 清单不能自动当作 CPU 资源。显示“被占用”时仍可预约未来时段，开始前须与当前使用人协调；预约不会自动启动或停止任务，预约空档不能证明 GPU 实际空闲。

### 桌面端首次连接与同步

1. 在预约网页注册并请超级管理员分配公司；站点所有者使用显式部署命令创建超级管理员，旧资源管理员保留原角色。普通成员不需要安装 RackTop，就能用浏览器预约。
2. 在 RackTop 左侧打开 **「团队预约」**，点击 **「账号登录」**，输入网页上注册的成员名称和密码（旧账号使用原用户名）。这里取得的是独立的 30 天设备登录，网页的「记住登录」不控制设备有效期；网页登录和桌面登录也不会互相自动登录。
3. 管理员会看到 **「同步本机资源」**。先让待共享机器在 RackTop 中完成 SSH 连接并采集最新 GPU 信息，再勾选需要加入团队目录的机器，点击 **「保存并同步」**。只同步勾选的机器，最多 32 个本地连接；首次同步要求 90 秒内的完整在线 GPU 采样。
4. 检查各机器旁的上报时间或错误信息；只有服务确认后的资源才出现在 **「团队资源」** 中。点击资源上的 **「查看与预约」** 会打开网页并定位、高亮同一机器。预约创建、续约和取消在网页中完成，桌面显示同一份中央排期。
5. RackTop 运行期间每 30 秒同步所选资源。取消勾选后点击保存，或点击 **「退出账号」**，会停止相应上报；已有资源和预约仍保留。需要让同事停止预约时，在网页 **「资源管理」** 中停用资源。

如果交付时已经预配置本机资源绑定，首次以管理员身份登录会接续该绑定；这不等于预设了管理员账号或免密码授权。普通成员首次登录不会接管预配置，切换到另一个账号也不会继承前一账号的同步选择。同一账号退出再登录可保留原绑定。

系统钥匙串锁定时，应先解锁再登录或同步，程序不会改用明文文件保存设备令牌。设备过期或网页改密后，重新在桌面登录即可恢复账号连接；再次确认勾选和上报结果。电脑关机、休眠或断网会中断采集，但不会停止公网网页，也不会删掉未来预约。

| 页面提示 | 处理方式 |
| --- | --- |
| 没有「同步本机资源」 | 当前是普通成员；资源目录由管理员维护。 |
| 首次加入需要完整在线 GPU 清单 | 在 RackTop 连接该机器并检查驱动采样，再重新同步；CPU 资源在网页手工登记。 |
| 状态未知／最后更新时间较早 | 网页仍可预约未来时段；实时状态需等待桌面恢复上报。 |
| 硬件变化待核验 | 管理员在网页协调原预约后确认新清单，不要按新编号重新创建重复机器。 |

独立部署、升级、备份及可选的一次性清单导入见 [部署说明](deploy/README.md)。

## 预约规则

- 整机与同一资源的所有 GPU 预约互斥；指定 GPU 不相交时可以并行。前一预约结束时刻等于下一预约开始时刻，不算冲突。
- 创建、修改和续约在 SQLite 事务中统一检查冲突；多客户端并发不会同时预约同一时间段的同一 GPU。
- 修改提交预约 `version`，同步资源还需提交最新 `inventoryVersion`，旧页面会提示刷新而不会覆盖新数据。
- 每次最长 7 天，只能预约未来 90 天内的时间；已经开始的预约不能修改开始时间。页面按北京时间显示，服务端保存 UTC 时间。
- 已取消、已结束和已到期记录保留。取消或提前结束释放未来排期，不代表后台训练已终止。
- 业务 API 没有匿名查看白名单；account 模式未分配公司时也不可访问业务。具备业务访问资格的成员可查看本公司的完整资源和排期，包括备注、预约用途与待确认 GPU 清单；这些字段不应用于保存秘密。

接口字段、成员访问权限、设备认证和错误码见 [API.md](API.md)。

## 本机开发与测试

需要 **Node.js 24+** 和 npm，在仓库根目录运行：

```bash
npm ci
```

## 可选飞书模式与群通知

`TEAM_AUTH_MODE=feishu` 是独立的可选认证模式，不是用户名登录的必需依赖。正式使用需 HTTPS、飞书应用、`FEISHU_APP_ID` / `FEISHU_APP_SECRET`、租户白名单 `FEISHU_TENANT_KEYS` 和可选管理员 `FEISHU_ADMIN_OPEN_IDS`；回调路径为 `/api/auth/feishu/callback`。飞书账号与本地账号不自动合并，管理员判断依据平台身份 ID，不能用姓名替代。切换模式前备份数据并核对账号与已有预约的关系。飞书模式仍要求登录后浏览业务数据。

可选群机器人配置 `FEISHU_WEBHOOK_URL` 和 `FEISHU_WEBHOOK_SECRET`，适用于正式账号模式或飞书模式。未配置时不会发送；创建、修改、取消、提前结束和临近结束的通知失败不会撤销预约。后台默认每 30 秒处理最多 5 条，失败退避重试；未启用期间的历史事件不补发。崩溃时发送与确认可能重复，不承诺恰好一次或个人私信。启用前用测试群核验内容，预约用途不应包含秘密。

飞书权限与组织可用范围需另行实际验证。现有 Docker / Compose / Caddy 材料是其他部署方式的参考，本次交付采用上面的 systemd / Nginx 方案，不能据此宣称容器或飞书生产登录已通过验收。

## 资产设备管理

同一账号可使用[资产设备管理](../docs/EQUIPMENT.md)。列表 `/equipment`、扫码详情 `/equipment/<设备UUID>`、历史和照片均需业务成员身份（已分配公司或超级管理员），普通成员可以录入和维护设备。

新建必填名称、类别和位置；成员新建设备默认所属账号公司，超管新建时须选择设备公司。普通成员的设备公司下拉只允许自己公司，超管可跨公司调整；设备与员工公司独立保存。旧设备空公司只对超管显示“待分配”，分配后才允许对应公司成员访问。类别限定为机械臂、台式主机、笔记本电脑、显示屏、摄像头模组、实验物料、小推车、夹爪，位置限定为上海、太仓。笔记本电脑在英文界面显示为 Laptop，可用于设备登记、编辑、统计和设备申请。历史非标准值保留展示，下次编辑、领用或归还时须重新选择，不自动猜测映射。

设备 `serialNumber` 是从 `00000001` 递增的八位数字字符串，服务端分配且不可修改，数据库也防止改号和回收已提交的编号。旧自由序列号保留为只读 `legacySerialNumber`，原 `code` 和 UUID 不变，旧二维码继续有效。标签是“固定资产标识码”表格，包含公司名称、资产编号、资产名称、责任人、使用人和二维码，可通过“打印标签”导出完整 PDF 或 PNG。档案更新不改变二维码，但纸面文字需重新打印。

负责人 `responsiblePerson` 与使用人 `currentUser` 独立。新建负责人默认当前成员姓名；领用默认把当前姓名填为使用人并设为使用中，归还清空使用人并设为可用，负责人不自动变化。它们是台账文本，不决定访问权限。

设备目录直接显示照片缩略图，无照片时显示占位。每设备一张照片，可拍摄、选择、预览后保存、更换或删除。网页预压缩，服务端再次解码校验，最终以最长边不超过 1600 像素、大小不超过 512 KiB 的 JPEG 存入同库 `equipment_photos` BLOB，原图及 EXIF 不持久保存。照片 GET 需要身份且禁缓存；POST 和 DELETE 提交当前设备 `version`，与文字编辑共用 CAS 和修改历史。冲突、注销或失败不会覆盖旧图；服务关机等在途处理结束后才关闭数据库。完整接口及上传大小边界见 [API.md](API.md)。
