RackTop 桌面在「密钥管理」和「日志」之间提供 **团队工作台**：悬停或键盘焦点会展开子项，方向键可选择，Escape 关闭；点击主按钮打开网页首页。原「团队预约」桌面页继续提供本机资源同步与中央排期。

## 注册与公司

新成员只填写一个名称和密码注册，不需要邮箱。名字用于登录和显示；旧账号原用户名仍能登录，不改变原账号身份。注册后由超级管理员分配 A公司、B公司、C公司或西浦，再使用业务页面。一个成员可以同时加入多个组织：超级管理员在「成员管理 → 公司」勾选多个组织并保存。

设置中可选择24种彩色内置SVG头像，涵盖人物、动物、机器人、科技和自然元素；原7个ID保持兼容，保存后其他会话也会显示，自己的公司只读。网页勾选「记住登录」有效 360 天，不勾选为 8 小时，桌面设备令牌仍为 30 天；退出或密码重置可以提前撤销。详细流程及忘记密码处理见[账号指南](TEAM_ACCOUNTS.md)。

普通成员和资源管理员通过「当前组织」选择所属组织，页面只显示该组织的业务；桌面「团队预约」也可切换组织。切换时旧列表和未保存的表单会关闭，请先保存工作。超管没有公司归属并可跨公司管理。未分配公司的旧资源与设备只向超管显示，核实公司后再开放。改变成员归属不会把旧公司的资产、预约或周报一起迁移。

## 统一管理 SSH 服务器

1. 管理员打开「服务器资源 → 添加服务器」，填写组织、名称、主机地址、端口和 SSH 用户名，需要时填写一台跳板机。使用密码登录时，可填写「共享 SSH 密码」和独立的「共享跳板机密码」。填写服务器现有密码；这里不会修改服务器账号本身的密码。
2. 点击该服务器的「授权」，勾选同组织成员并保存。同组织管理员可以维护该组织的服务器；普通成员只收到获授权的服务器。
3. 成员在桌面 RackTop 的「团队预约」登录同一个账号。资源列表约每 30 秒同步一次，获授权的服务器自动出现在左侧列表，无需逐台抄写地址。
4. 使用桌面 2.7.0 或更新版本时，管理员已设置的共享密码会在连接时自动使用，无需成员重复输入。没有共享密码的目标机，仍需打开「编辑配置」选择本机已有的私钥、SSH Agent 或密码。中央维护的地址不可在成员电脑上改写；私钥不上传。

管理员编辑时，密码框留空保留原密码，填写新值替换，勾选「清除已保存的共享密码」才删除；目标机与跳板机分别处理。改变对应主机地址、端口或用户名会清除旧密码，除非同次填写新密码。配置文件不含密码，导入后可逐台编辑补充。网页只显示是否已配置，不回显已保存的明文；成员需要升级桌面客户端才能使用共享密码，旧客户端的原本连接方式继续可用。

超级管理员也可点击「导入 SSH 配置」（或「添加服务器 → 从 SSH 配置文件导入」），选择桌面导出的 `RackTop_ssh_….conf`，预览并勾选服务器，再选择所属组织及授权成员后导入。一次最多 50 个 Host 段、文件最大 1 MiB。可以导入名称、地址、端口、SSH 用户名和单台跳板机；配置文件在浏览器中解析，不上传密码、私钥或本机密钥路径。

同一组织内相同地址、端口、用户名及跳板机的连接会跳过，已有名称、启用状态和成员授权保持原样；需要调整已有服务器时使用「编辑」或「授权」。保存采用一个事务，有无效数据时整批不保存；网络超时后可刷新核对再重试，同样的连接不会重复添加。普通 SSH 配置须使用独立 Host 段并明确填写 User；Include、Match、通配或多别名 Host、ProxyCommand 和多跳路由不支持，页面会提示具体行号。

网页中的资源列表在页面可见时约每 30 秒检查更新，返回页面时也会检查；编辑或导入期间暂停自动刷新，避免打断未保存的操作。获授权成员无需重新登录。

管理员修改连接或共享密码后，客户端接收到变更会停止原连接，并在后续操作中使用新状态；共享密码被清除时，需重新确认本机认证。收到撤权、停用、退出或组织切换时，也会停止受影响的连接；这采用轮询，并非即时推送。无法验证云端权限时暂停团队连接。每次成功同步会续期 75 秒的本机授权，未能续期时到期也会停止受影响的连接。本机个人服务器不受影响，已有历史仍保留。

服务器资源保存连接元数据、成员授权和管理员主动设置的加密密码，不会把已有个人连接或私钥自动上传。密码领取使用独立的设备接口，每次重新检查组织和授权，桌面仅在原生进程内存中使用，不写入配置、历史、导出文件或系统钥匙串。目录权限控制 RackTop 内的团队连接，不能替代服务器本身的 SSH 账号管理；如果成员已经知道密码，要禁止其用其他 SSH 工具登录，仍需在服务器上修改密码。

## 周报功能移除与旧入口

2.8.0 源码已移除周报编写、评审和统计界面，以及桌面和网页导航中的周报入口。旧桌面安装包或书签仍可能打开 `/reports`；新网页在完成登录与公司检查后显示“周报功能已移除”，可返回资源看板。

`/api/workspace/reports` 及全部子路径在原有身份、公司及写入校验通过后统一返回 `410 REPORTS_REMOVED`。历史周报、评分和审计继续保存在原数据库及备份中，不因功能移除而删除；新网页不再提供它们的浏览、编辑或导出入口。

## 办公设备申请

员工在「办公设备申请 / Office equipment requests」填写类别、数量与用途，可以关联本公司一台可用设备；关联已有设备时数量必须为 1，类别须一致。不关联现有设备时可提交新设备需求，数量为 1–999。超级管理员不提交自己的申请，只在同一页面处理成员申请。

提交成功只返回申请编号和确认信息，**提交人不能在网页读取申请内容或处理进度，也不能查看其他人的申请**。请保留编号，需补充或确认处理结果时联系超级管理员。服务端直接访问申请详情同样受此限制。

只有超级管理员可查看申请目录、原始内容和处理历史。处理流程为待处理 → 批准或拒绝；批准后才能登记领取。已领取记录不能退回旧状态，原类别、数量、用途和关联设备不能被审批动作改写。

关联现有设备的领取会核实申请人仍属于原公司、设备仍同公司且类别一致、状态可用并且没有使用人。检查通过后，在同一个数据库事务中将使用人设为申请人当前姓名、设备状态设为使用中，并更新申请状态、设备记录及两套审计；任何一步失败全部回滚。负责人保持不变。

未关联现有设备的申请批准或领取，只记录人工处理结果，不会自动采购或创建资产。设备归还仍在设备详情登记，申请记录保留为已领取历史。设备的直接领用/归还登记继续向本公司成员开放，这个申请流程不是对所有设备操作的强制审批拦截。

## 算力预约与资产设备管理

算力目录可从桌面已选服务器同步 GPU 身份，或由管理员手工登记。资源按公司隔离；超管在资源管理中补齐旧资源的公司，跨公司调整须提交最新公司版本，有未结束的有效预约时拒绝调整。预约只用于排期协调，不锁卡、不中止训练，也不授予 SSH 权限。详见[预约使用说明](../team-web/README.md)。

### GPU/CPU 分类与当前占用

资源看板按 **GPU 集群 / CPU 集群** 分组，再按原有集群名称筛选；分类依据是 GPU 数量，集群名称不会被自动改成云厂商名称。管理员手工登记时可选 GPU 或 CPU：GPU 需要型号和 1–64 张卡，CPU 保存为 0 张 GPU、空型号且只支持整机预约。同步资源的类型与 GPU 信息由硬件来源决定，不能在网页手工切换。

2.8.0 管理员桌面通过本机已有 SSH 连接采集获授权组织服务器，约每 30 秒上传 GPU 占用摘要；云端网页通过 API 读取摘要，不直接连接 SSH。关闭本地历史记录后仍可同步实时占用：桌面使用内存中的摘要，不为此额外持久化完整采样。摘要包含每卡利用率、已用显存及检测到的 Linux 系统用户名。系统用户名不是团队账号或预约人；检测到占用但没有可用用户名时显示“匿名用户”。

“当前实际占用”与“所选时段预约”分别展示。采样达到 90 秒或缺少可靠数据时显示未知，并隐藏旧占用用户；旧客户端没有新摘要时同样显示未知。显示“被占用”时仍可预约未来时段，开始前应与使用人协调；预约不会自动启动或停止任务，排期空档不能证明硬件空闲。

CPU 服务器须由管理员按实际节点登记，支持分类和整机预约；本轮实时占用采集覆盖 NVIDIA GPU，不提供通用 CPU 占用监控，也不根据空 GPU 清单自动推断 CPU 资源。

### 资产设备管理

设备目录提供照片缩略图，固定八位编号、二维码、负责人和使用人保持独立。设备目录逐行标明公司；超管的公司筛选固定列出四家公司和数量，即使某公司还没有设备也会显示0，另可查看待分配设备。普通成员的公司只读且仅显示自己公司；超管在具体公司筛选下新建时会预选该公司，仍需核对后保存。手机拍照、压缩、打印资产标签与历史规则见[设备指南](EQUIPMENT.md)。

## 数据保存范围

工作台数据库保存账号资料、头像选择、公司、资源清单、预约、设备与压缩照片、历史周报、申请和审计，以及管理员维护的服务器资源与加密共享密码。2.8.0 源码另保存经授权上报的 GPU 占用摘要，包括 Linux 系统用户名；存储与接口已随网页上线，真实占用仍需新版管理员桌面采集后才能出现。本机个人连接、私钥和进程明细不会自动上传；本机连接导入导出在桌面 **SSH 配置** 中完成。

这些业务表与已有预约共用 SQLite，一致性备份脚本覆盖全部数据。共享密码恢复还需要与密文匹配的独立加密密钥；只备份数据库不足以恢复密码。删除账号不删除历史，重新注册同名账号不会继承原 UUID 的权限。运维恢复时保留数据库完整快照和独立密钥恢复材料，操作说明见[部署指南](../team-web/deploy/README.md)。
