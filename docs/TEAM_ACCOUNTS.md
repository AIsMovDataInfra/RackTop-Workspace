# 团队账号与公司管理

本页适用于RackTop **2.1.0** 团队工作台；网页主字为RackTop，辅助字为“AIsMov · 团队工作台”。正式服务使用 `TEAM_AUTH_MODE=account`，账号、公司和业务数据仍在同一数据库。本轮部署与完整验收尚待完成，见[2.1.0验证记录](VERIFICATION_2_1.md)；上一版[2.0.0验证](VERIFICATION.md)保留。

## 员工注册与使用

新员工在网页只填写一个**成员名称**和密码注册，不需要另外填写用户名或邮箱。名称用于登录和显示，支持中英文；去除两端空白后非空即可，不另设长度或字符格式限制，不做 Unicode 规范化，保留输入字符，不允许重名。登录忽略名称两端空格和大小写。密码须有非空白内容，保留输入中的空格，没有复杂度或最小长度要求。服务端仍用固定 UUID 和会话判定权限。

已有账号的原用户名、显示姓名与 UUID 均保留，不会合并或改名；原来两个名称不同时，继续使用原用户名登录，在设置中可查看。兼容旧客户端的双字段注册接口继续保留，新网页只显示一个名称输入。

在网页「设置 → 我的资料」可从24种彩色内置SVG头像中选择，并点击「保存头像」。人物、猫、狗、火箭、机器人、花和星星等原7种继续兼容，另有工程师、兔子、卫星、行星等选项；不依赖系统emoji字体或外部图片。头像保存后在账号其他会话显示，未知ID回退人物，不改变身份权限。个人资料中的公司只读，只有超级管理员能在成员管理中分配。

网页登录勾选「记住登录」为 **360 天**，不勾选为 **8 小时**；桌面设备令牌仍为 **30 天**。已有登录的到期时间不会凭空延长，重新登录时按新规则计算。退出注销当前网页会话；改密或管理员重置撤销旧网页和桌面会话。

新注册员工的公司为「待分配」。请把自己的用户名告知超级管理员，由对方在「成员管理」分配公司，再刷新网页或桌面团队登录状态。公司只能选择 **A公司、B公司、C公司、西浦**，员工不能自行填写或更改。

分配公司后才能查看资源、排期、设备、照片和登记历史，或提交预约、登记设备。未分配时仍能登录、退出、修改自己的密码和提交找回申请。直接访问设备二维码地址也遵循相同规则；登录和公司检查通过后继续打开原设备。

公司是业务访问边界：普通成员和资源管理员只可查看、预约或维护自己公司的资源和设备，跨公司详情和照片不可通过直接 URL 读取。超级管理员可跨公司管理。旧资源或设备没有明确公司时，只向超级管理员展示，由其核实后分配；不会根据创建者猜测。

成员名册和按周/公司/成员汇总的周报统计均仅超级管理员可读。周报进一步限制为作者、指定同公司评审人和超管可见，设备申请正文仅超管可读，员工提交后只得到编号确认；详见[工作台指南](WORKSPACE.md)。员工调公司不会带走原公司的资产、预约或周报记录。

## 超级管理员与资源管理员

| 身份 | 权限 |
| --- | --- |
| 超级管理员 | 站点内唯一，账号由运维显式创建；可访问「成员管理」，查看已登记账号资料、增加或删除员工、分配公司和重置员工密码，同时具有资源管理权限 |
| 资源管理员 | 原有 `role=admin` 账号；可管理本公司资源和预约，不能访问成员名册、分配公司或重置员工密码；也需要先分配公司才能继续业务操作 |
| 团队成员 | 公司分配后可预约和维护本公司设备，预约修改仍限本人或本公司资源管理员；不能查看其他成员的账号资料或管理员工 |

超级管理员由独立的 `isSuperAdmin` 标记确认，`role=admin` 本身不会获得成员管理权限。约定的超级管理员用户名为 `admin`，源码、环境模板和服务器启动流程都没有内置初始密码；实际密码只由运维在初始化时输入。超级管理员可给自己分配公司，无公司时仍能进入管理界面处理其他员工。

成员管理显示名称、头像、公司、身份、注册时间与找回申请状态，兼容显示旧账号的原用户名，不展示原密码或登录凭据。超管新增员工同样填写一个名称、密码和四家公司之一，身份固定为团队成员。账号名称须保持唯一。

## 忘记密码

1. 在登录页选择「忘记密码」，填写登录名称（旧账号填写原用户名）并提交申请。
2. 联系超级管理员核实身份。网页不会发送邮件、短信或其他消息，也不会自动生成或公开新密码；无论用户名是否存在，提交结果都使用同一提示。
3. 超级管理员在「成员管理」筛选找回申请，核实本人后设置新密码，并私下告知该员工。
4. 员工使用新密码登录；如有需要，可在设置中自行修改密码。

重置会退出该员工的全部网页和桌面设备会话，清除待处理申请；设备同步需重新登录。申请本身不会改变密码或退出已有会话。成员信息变化时会提示版本冲突，应读取最新信息后核对再提交。

超级管理员不能通过员工重置入口重置自己；已登录时可在设置中修改自己的密码，遗忘时使用下面的运维 `reset` 命令。

## 删除员工与历史记录

删除员工会立即撤销其全部网页登录和桌面设备登录，释放用户名和姓名供以后重新添加。原账号的 UUID 作为已删除身份保留，不再出现在有效成员名册中；预约、设备、照片和登记历史不会随删号消失。

重新创建相同用户名或姓名会得到新的 UUID，不会继承旧账号的预约所有权或登录状态。超级管理员账号不能在成员管理中删除。负责人和使用人是设备档案中的独立文字字段，删号不会自动改写这些历史资料，设备后续交接需在台账中登记。

## 运维初始化与遗忘恢复

先按照[部署说明](../team-web/deploy/README.md)准备服务用户、目录和一致性备份。以下示例在服务器的 Bash 中执行，路径沿用部署约定。数据库及其目录由 `racktop-team` 所有，命令也以该用户运行，避免创建 root 所有的数据库或 WAL 文件。

首次创建：

```bash
set +x
sudo -v
read -r -s -p '输入超级管理员初始密码：' racktop_admin_password
printf '\n'
printf '%s\n' "$racktop_admin_password" | sudo -n -u racktop-team \
  /opt/racktop-team/node/bin/node /opt/racktop-team/current/scripts/team-admin.mjs create \
  --db /var/lib/racktop-team/team.sqlite --public-url https://136.0.110.161 \
  --username admin --name 超级管理员
unset racktop_admin_password
```

密码只从标准输入传入，不写入参数、文件或环境变量。`create` 重复执行时保持原账号和原密码，不会重新初始化；如果已经存在同名普通账号，或存在另一个超级管理员，脚本会明确拒绝，必须先核实已有账号身份，不能静默提升权限或抢占账号。

超级管理员遗忘密码时，在完成运维身份核验与备份后，明确执行 `reset`：

```bash
set +x
sudo -v
read -r -s -p '输入超级管理员新密码：' racktop_admin_password
printf '\n'
printf '%s\n' "$racktop_admin_password" | sudo -n -u racktop-team \
  /opt/racktop-team/node/bin/node /opt/racktop-team/current/scripts/team-admin.mjs reset \
  --db /var/lib/racktop-team/team.sqlite --public-url https://136.0.110.161 \
  --username admin
unset racktop_admin_password
```

`reset` 只处理已经存在且用户名匹配的超级管理员，撤销其全部网页和桌面会话，保留资源、预约、员工和设备。此命令不应加入开机任务或每次部署脚本。脚本输出操作结果和账号资料，不输出密码。

站点使用其他公开地址时，将示例中的 `--public-url` 替换为真实 HTTPS 根地址；CLI 使用生产认证约束，本机临时数据库初始化也可使用 `https://127.0.0.1`。Docker 容器内使用同一脚本和持久库路径，以容器的低权限服务用户运行。

## 现有站点升级

升级不会自动把已有资源管理员提升为超级管理员，也不会猜测成员或旧设备所属公司。先保留完整数据库快照，再创建唯一超级管理员，为现有成员分配公司，并在资源管理、设备管理中核实未分配的资源与资产；**已有资源管理员也需分配公司后才能继续 RackTop 资源同步**。登录可继续有效，业务接口会在公司待分配时返回 `COMPANY_REQUIRED`。

设备的公司与员工的公司独立保存。员工新建和编辑设备的公司下拉只能选择自己公司，服务端同样检查；超级管理员可以选择任意一家公司，并可在以后跨公司调整设备。员工调公司不会迁移以前登记的设备，其他成员编辑、领用或归还也不会改动资产所属公司。旧设备仅超级管理员可见，显示「待分配」并由其补齐；设备编号、二维码和历史继续保留。标签格式和照片规则见[设备管理说明](EQUIPMENT.md)。

资源公司也独立保存。调整已分配资源的公司需要最新 `companyVersion`，有未结束的有效预约时拒绝调整；结束或取消后再核实移交。已结束预约保留其原公司及资源名称快照，不随资源移交泄露给新公司。

验收时核对：新注册账号待分配、旧资源管理员不具有成员管理权限、超级管理员可分配公司、分配后网页和桌面可用、找回申请与重置生效、旧会话失效、删号后历史保留，以及同名新账号不能操作旧账号预约。不要把测试员工写入真实生产台账。
