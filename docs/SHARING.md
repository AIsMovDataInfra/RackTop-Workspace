# RackTop 资源共享

适用版本：`2.2.0` 测试候选。修改时间：2026-09-09 16:39:04 +08:00。

本页描述正在准备的 2.2.0 行为。公开标签、Linux 与 Mac 安装包、更新清单、生产中继部署和本机安装均尚未完成；当前已经公开并通过核验的版本仍是 [2.1.1](https://github.com/AIsMovDataInfra/RackTop-Workspace/releases/tag/v2.1.1)。

通过“资源共享”，接收者可以在自己的 RackTop 中使用分享者已经连接的服务器，获得获准的实时监控、终端命令和文件上传下载能力。双方可以处于不同网络，不需要 VPN，也不需要在 A100 等目标服务器上添加接收者的 SSH 公钥。分享者电脑是实际网关，目标服务器的 SSH 凭据始终留在分享者电脑。

## 使用前提

- 分享者和接收者都需要包含相同共享协议的 RackTop 2.2.0 客户端。Linux amd64、Mac Apple Silicon 和 Mac Intel 使用同一产品版本；安装包按平台和架构区分。本轮三平台公开包仍待构建和发布。
- 分享者应先在本机 RackTop 中正常连接目标服务器，完成 SSH 主机指纹确认，并保证本机私钥、SSH Agent 或密码仍可用。
- 双方需要能够访问固定中继 `https://136.0.110.161` 的 HTTPS/WSS 443 端口。生产中继仍待部署本轮访客公网出口 IP 元数据能力。
- 分享者首次使用需要配置中继访问令牌；接收者只需要分享者提供的邀请码，无需持有中继管理令牌。
- 文件服务要求目标服务器为具备 Python 3 的 Linux 环境，不需要安装第三方 Python 包。

## 分享一台资源

1. 打开侧栏“资源共享”，选择“我共享的资源”。若尚未配置，进入“中继设置”填写访问令牌；已保存的令牌不会回显。
2. 创建共享，选择本机已有服务器，填写共享名称、访问有效期和默认目录，再选择实时监控、终端命令、文件传输能力。
3. 生成邀请码并复制给受信任的接收者。界面持续保留当前邀请码及过期时间，可在有效期内反复复制；默认邀请有效期为 10 分钟。
4. 同一邀请码在到期前可供多台设备依次加入，直到达到每个共享的成员上限。每台新设备生成自己的设备密钥并形成独立成员记录，拥有各自的在线状态、连接和撤销边界。
5. 成员在线时，分享者可在成员列表看到该连接的公网出口 IP；离线后不再显示该地址。成员名称和设备身份仍是授权依据，IP 只用于辅助识别当前连接。

成功加入一台设备不会消费或删除邀请码。已绑定设备在共享有效期内通过本机保存的设备身份重新连接，不需要再次输入邀请码，也不需要在目标服务器添加公钥。邀请码到期后不能再添加新设备，但不会撤销已经绑定且仍在共享有效期内的成员。

邀请码是一项临时加入凭据，拿到有效邀请码的人都可以发起绑定。只应将它交给受信任的接收者，不应发布到公开群聊、网页或日志。撤销任一成员时，RackTop 会同时轮换当前邀请码：旧码立即失效，分享者可以复制新码继续邀请；仍获授权的其他成员继续使用自己的设备身份。

“暂停”会停止该资源的全部共享访问，恢复后已授权设备可重新连接。“撤销成员”移除该设备的授权并轮换邀请码。“删除共享”移除该资源的共享入口、邀请码及全部成员授权。这些操作均不会删除目标服务器上的项目文件。

## 加入并使用共享

1. 选择“别人共享的资源”，点击“加入共享”。
2. 粘贴完整邀请码，填写让分享者容易识别的设备名称。
3. 加入后选择资源，根据授权打开实时监控、终端命令或文件传输。

资源信息不会向接收者提供分享者的本机 SSH 配置或私钥。临时网络中断后，客户端会尝试重新连接；也可以手动断开、连接，或将资源从本机移除。重新连接会建立新会话，不恢复旧终端或未完成的文件传输。

实时监控展示服务器的 CPU、内存与 GPU 等当前采样。独立共享终端支持输入、窗口尺寸调整和退出反馈；终端输入、输出与关闭操作均归属于当前资源和会话。

文件页面以共享默认目录为根，使用相对路径浏览。可以进入子目录、返回上级、刷新，以及通过原生文件对话框上传和下载文件。传输显示进度并支持取消；文件数据由原生层按 48 KiB 分块处理，完整传输执行 SHA-256 校验，不把整个文件载入网页内存。

## 在线状态与公网出口 IP

分享者电脑必须持续在线。存在未暂停且未过期的共享时，关闭 RackTop 窗口会保留托盘后台运行；完全退出应用、电脑休眠、断网或 SSH 凭据不可用都会中断访问。接收者无法绕过离线的分享者直接连接目标服务器。

分享者看到的是访客连接公网中继时的**公网出口 IP**，不是访客电脑的局域网地址。多人处于同一家庭、实验室或公司 NAT 后方时可能显示同一个 IP；VPN、代理、移动网络或运营商级 NAT 也可能改变或共享该地址。因此它不能证明人员身份、设备唯一性或精确地理位置，不能替代设备密钥和成员授权。

IP 仅随当前在线成员状态显示，访客离线后界面不保留历史地址。生产中继应只从受信任的本机 Nginx 代理链取得连接地址，不能相信公网请求自行填写的转发头；该能力部署并完成真实公网验收前不得视为已经上线。

## 权限与安全边界

双方主动连接公网中继，业务通道在 WSS 内再建立端到端 TLS。接收者校验邀请码携带的分享者证书；分享者验证设备签名，并在请求执行前检查共享、设备和能力授权。中继转发业务密文，仍能观察连接地址、路由和流量等传输元数据。

共享身份私钥、设备私钥、中继令牌及重连凭据保存在各自电脑的操作系统钥匙串中；钥匙串不可用时不会回退到明文文件。用于登录目标服务器的 SSH 私钥继续使用分享者已有的本机凭据配置，不发送给接收者或中继，也不写入源码和邀请码。分享者保存的中继管理令牌不会交给接收者。

**开放任意终端命令意味着接收者使用分享者的同一个远端账号。** 默认目录只是终端起始位置，不能隔离文件、GPU、进程或账号权限。文件页面的路径限制不约束终端命令；此功能不提供多用户强隔离。暂停、撤销或断开会关闭共享会话，但不能保证终止已经通过 `nohup`、`tmux` 等方式脱离终端的远端后台任务。

## 当前容量与限制

| 项目 | 当前范围 |
| --- | --- |
| 共享有效期 | 最长 7 天；界面提供 1 小时、24 小时、7 天 |
| 邀请有效期 | 默认 10 分钟；到期前可重复复制并供多台设备依次加入 |
| 本机创建的共享 | 最多 8 个，过期记录需手动删除后释放名额 |
| 每个共享的成员 | 最多 8 台设备，每台独立授权；邀请入口和成员路由均受中继总量限制 |
| 本机保存的接收资源 | 最多 32 个 |
| 中继路由 | 最多 64 条 |
| 中继同时连接 | 最多 16 个房间、32 个 WebSocket 连接 |
| 本机文件传输 | 同时最多 4 项，单文件上限 100 GiB |
| 文件目录列表 | 最多扫描 2,000 个条目，且受响应大小限制；截断时明确提示 |
| 客户端发送节流 | 每个连接的每个发送方向约 1.5 MiB/s，包含协议开销 |
| 中继流量限制 | 每个房间双向合计 4 MiB/s；并非整个中继的总带宽限制 |

文件传输不支持跨连接续传、目录递归传输或覆盖已有目标。目标同名文件已存在时返回冲突，需要选择新名称或先自行处理原文件。取消、失败或断开会清理本次传输拥有的临时文件；符号链接和越过共享根目录的路径不允许通过文件服务访问。实际速度还受分享者电脑、目标服务器及双方网络影响。
