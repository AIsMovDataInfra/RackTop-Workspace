# RackTop 资源共享

适用版本：`1.26.0-linux.8`。修改时间：2026-09-08 06:06:03 +08:00。

通过“资源共享”，接收者可以在自己的 RackTop 中使用分享者已经连接的服务器，获得获准的实时监控、终端命令和文件上传下载能力。双方可以处于不同网络，不需要 VPN，也不需要在 A100 上添加接收者的 SSH 公钥。

## 使用前提

- 双方都需要包含此共享协议的新版 RackTop。当前实现位于本 Linux 社区 fork；现有上游 Windows/macOS 安装包不能直接加入。本轮未构建或验证 Windows/macOS 版本。
- 分享者应先在本机 RackTop 中正常连接目标服务器，完成 SSH 主机指纹确认，并保证本机私钥、SSH Agent 或密码仍可用。
- 双方需要能够访问当前固定中继 `https://136.0.110.161` 的 HTTPS/WSS 443 端口。此版本不能在设置中切换到任意中继地址。
- 分享者首次使用需要配置中继访问令牌；接收者只需要邀请码，无需持有这个管理令牌。
- 文件服务要求目标服务器为支持当前文件工作进程的 Linux 环境，具备 Python 3；不需要安装第三方 Python 包。

## 分享一台资源

1. 打开侧栏“资源共享”，选择“我共享的资源”。若尚未配置，进入“中继设置”填写访问令牌。已保存的令牌不会回显。
2. 创建共享，选择本机已有服务器，填写共享名称、访问有效期和默认目录，再选择实时监控、终端命令、文件传输能力。
3. 复制新生成的一次性邀请码，交给指定接收者。界面显示邀请码的过期时间；默认邀请有效期为 10 分钟。
4. 接收者成功配对后，成员列表会显示其设备名称和连接状态。每台新增设备都应使用新的邀请码。

邀请码用于首次绑定设备身份。成功兑换后，其他设备不能再次兑换；已绑定设备在共享有效期内通过本机保存的设备身份重新连接，无需重复添加远端公钥。邀请码应完整传递给指定接收者，不应公开发布。

“暂停”会停止该资源的共享访问，恢复后已授权设备可重新连接。“撤销成员”只移除该设备的授权。“删除共享”移除该资源的共享入口及其成员授权。这些操作均不会删除目标服务器上的项目文件。

## 加入并使用共享

1. 选择“别人共享的资源”，点击加入共享。
2. 粘贴完整邀请码，填写让分享者容易识别的设备名称。
3. 加入后选择资源，根据授权打开实时监控、终端命令或文件传输。

资源信息不会向接收者提供分享者的本机 SSH 配置或私钥。临时网络中断后，客户端会尝试重新连接；也可以手动断开、连接，或将资源从本机移除。重新连接会建立新会话，不恢复旧终端或未完成的文件传输。

实时监控展示服务器的 CPU、内存与 GPU 等当前采样。独立共享终端支持输入、窗口尺寸调整和退出反馈；终端输入、输出与关闭操作均归属于当前资源和会话。

文件页面以共享默认目录为根，使用相对路径浏览。可以进入子目录、返回上级、刷新，以及通过原生文件对话框上传和下载文件。传输显示进度并支持取消；文件数据由原生层按 48 KiB 分块处理，完整传输执行 SHA-256 校验，不把整个文件载入网页内存。

## 在线与权限边界

分享者电脑是实际网关，必须持续在线。存在未暂停且未过期的共享时，关闭 RackTop 窗口会保留托盘后台运行；完全退出应用、电脑休眠、断网或 SSH 凭据不可用都会中断访问。接收者无法绕过离线的分享者直接连接 A100。

双方主动连接公网中继，业务通道在 WSS 内再建立端到端 TLS。接收者校验邀请码携带的分享者证书；分享者验证设备签名，并在请求执行前检查共享、设备和能力授权。中继转发业务密文，仍能观察连接地址、路由和流量等传输元数据。

共享身份私钥、设备私钥、中继令牌及重连凭据保存在各自电脑的操作系统钥匙串中；钥匙串不可用时不会回退到明文文件。用于登录 A100 的 SSH 私钥继续使用分享者已有的本机凭据配置，不发送给接收者或中继，也不写入源码和邀请码。分享者保存的中继管理令牌不会交给接收者。

**开放任意终端命令意味着接收者使用分享者的同一个远端账号。** 默认目录只是终端起始位置，不能隔离文件、GPU、进程或账号权限。文件页面的路径限制不约束终端命令；此功能不提供多用户强隔离。暂停、撤销或断开会关闭共享会话，但不能保证终止已经通过 `nohup`、`tmux` 等方式脱离终端的远端后台任务。

## 当前容量与限制

| 项目 | 当前范围 |
| --- | --- |
| 共享有效期 | 最长 7 天；界面提供 1 小时、24 小时、7 天 |
| 本机创建的共享 | 最多 8 个，过期记录需手动删除后释放名额 |
| 每个共享的成员 | 最多 8 台设备 |
| 本机保存的接收资源 | 最多 32 个 |
| 中继路由 | 最多 64 条，成员和未兑换邀请均占用路由 |
| 中继同时连接 | 最多 16 个房间、32 个 WebSocket 连接 |
| 本机文件传输 | 同时最多 4 项，单文件上限 100 GiB |
| 文件目录列表 | 最多扫描 2,000 个条目，且受响应大小限制；截断时明确提示 |
| 客户端发送节流 | 每个连接的每个发送方向约 1.5 MiB/s，包含协议开销 |
| 中继流量限制 | 每个房间双向合计 4 MiB/s；并非整个中继的总带宽限制 |

文件传输不支持跨连接续传、目录递归传输或覆盖已有目标。目标同名文件已存在时返回冲突，需要选择新名称或先自行处理原文件。取消、失败或断开会清理本次传输拥有的临时文件；符号链接和越过共享根目录的路径不允许通过文件服务访问。实际速度还受分享者电脑、目标服务器及双方网络影响。
