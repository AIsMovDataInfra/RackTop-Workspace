# SSH 密钥管理

从左下角 **日志上方的「密钥管理」** 打开。此功能管理本机用于 SSH 登录的公钥和私钥，不管理 GPG 密钥、HTTPS 证书或服务器主机指纹。

## 查看和整理

- 打开时读取常用 SSH 目录及 RackTop 已配置的私钥路径；其他位置的文件可以用「导入已有密钥」登记。
- 通过名称、指纹或路径搜索，查看算法、公钥内容、文件位置和直接引用该私钥的 RackTop 服务器。
- 「重命名」修改显示名称，保留文件名；「移出列表」保留密钥文件和服务器配置。需要重新显示时，用原路径导入。
- 导入只记录本机路径，不复制或移动文件。公钥可以单独导入，但只有公钥不能用于身份认证。
- 不同文件即使包含相同公钥也可能分别出现；可比较 SHA256 指纹确认它们是否为同一个公钥。

## 手动生成

1. 点击「生成密钥」，填写便于辨识的名称。
2. 默认选择 Ed25519；需要兼容特定旧系统时可选择 RSA 4096。
3. 设置保护口令并再次确认，或明确选择不设置口令。
4. 点击「创建密钥对」。RackTop 调用本机 `ssh-keygen` 创建标准 OpenSSH 文件，已有文件不会被覆盖。
5. 选中新密钥，复制公钥内容，按服务器的正常授权流程把它加入目标用户的 `authorized_keys`。

新密钥存放在 `~/.ssh/racktop/keys/key-<随机标识>/`，公钥为私钥文件旁的 `.pub` 文件；显示名称和列表状态保存在 `~/.ssh/racktop/keys.json`。Linux 新建目录权限为 700，私钥权限为 600。备份时应保留密钥文件，不能只备份管理记录。

生成或导入密钥本身不会改变远端服务器的登录权限。管理界面只显示公钥和路径；保护口令不保存到 RackTop 配置，也不作为命令行参数传递。

## 用于 RackTop 连接

打开服务器的新增/编辑配置，在「私钥」认证下通过「选择已管理的密钥」选取已有私钥，也可以继续手动填写路径。保存后使用现有连接检查流程。

加密私钥需要先解锁到当前桌面会话的 SSH Agent。例如在本机终端运行 `ssh-add /path/to/private_key` 并输入口令，然后选择私钥或 SSH Agent 认证。此版本不在管理页面提供 SSH Agent 的解锁和移除功能。

## 范围和限制

- 本机文件操作仅在 RackTop 桌面版运行；浏览器预览可查看布局和表单，不读取或生成真实密钥。
- 此版本要求密钥与管理目录使用真实路径，不接受符号链接；多行授权列表、PuTTY PPK 和证书文件不能作为单个 OpenSSH 公钥导入。
- 私钥文件缺失、读取失败或公私钥不匹配时会显示相应提示；仅凭相同文件名不能保证配对。加密私钥需要解锁才能进一步验证。
- 关联服务器列表依据 RackTop 直接保存的私钥路径，不代表该密钥在其他软件、SSH Config、SSH Agent 或远端授权列表中的全部用途。
- 本次交付以 Ubuntu amd64 为验证平台；其他平台以版本验证记录为准。
